# Operations and Reproduction Procedure

## 1. Checkout and branch verification

```bash
git fetch origin
git checkout paper/strong-mechanism-safety-persistence
git status --short
git rev-parse HEAD
```

The worktree must be clean before freezing a command manifest or starting a formal run.

## 2. Create the strict 4070 Ti environment

Follow `paper/strong_mechanism/environment/INSTALL_4070TI.md`, then run:

```bash
python paper/strong_mechanism/scripts/check_training_environment.py
```

## 3. Validate static study state

```bash
make -C paper/strong_mechanism smoke
```

This checks source hashes, model pins, environment-lock consistency, schedule sums, seed matrices, statistics helpers, artifact generation, and LaTeX source completeness.

## 4. Prefetch the exact model snapshot

```bash
python paper/strong_mechanism/scripts/prepare_runtime_config.py \
  --config paper/strong_mechanism/configs/qwen3_4b_equal_dose_temporal_schedules.json \
  --output paper/strong_mechanism/data/runs/runtime_configs/prefetch_equal_dose.json \
  --verify-environment
```

Repeat with `--offline` to verify cache-only resolution. The path must end in the full registered commit.

## 5. Render and freeze the 15 formal commands

```bash
make -C paper/strong_mechanism commands
```

Review both generated files, run every `DRY_RUN`, then commit and record their SHA-256 values before the first formal model load. Do not regenerate after result access.

## 6. Non-formal smoke test

Use a separately named smoke config and a seed outside `{1,2,3}`. It may test one optimizer step and cleanup, but cannot produce or replace a formal result.

## 7. Run formal training

Execute the `FORMAL` commands in exact rendered order. `run_pinned_training.py` validates the pin and environment, resolves the exact model, writes provenance, refuses overwrite, invokes the canonical trainer, and preserves failures without silent retry.

## 8. Evaluate checkpoints

Use each machine-local runtime config. Generate identical prompt IDs and decoding across arms at checkpoints 0/6/16/32/48/64. Large generations remain outside Git; commit hashes, prompt-level labels, and lightweight summaries.

## 9. Run the registered gradient audit

For every arm and seed, use the runtime config generated by formal training:

```bash
python paper/strong_mechanism/scripts/run_registered_gradient_audit.py \
  --config <runtime-config.json> \
  --family risk \
  --seed <seed> \
  --arm <arm>
```

Before GPU execution, run the same command with `--dry-run`. The script computes weights from the registered schedule, audits steps 32/48/64, records both checkpoint and schedule step, freezes source-ID and schedule hashes, refuses output overwrite, and writes a normalized contribution table.

Do not use the historical `run_step2j_natural_gradient_audit.py` for principal equal-dose claims because it hard-codes the old decay schedule.

## 10. Blind quality review

Construct packets before joining arm keys. Review deliveries are immutable. Validate schema, calibration, hidden duplicates, and component reliability before adjudication. Freeze human-subset selection before model-review outcomes are opened.

## 11. Normalize and analyze

```bash
make -C paper/strong_mechanism analysis
make -C paper/strong_mechanism tables
make -C paper/strong_mechanism figures
```

All outputs derive from normalized files; no primary number is copied manually from a notebook.

## 12. Build manuscript

```bash
make -C paper/strong_mechanism/latex clean check
```

A release build must have no undefined references/citations, missing primary figures/tables, or `PENDING EVIDENCE` markers.

## 13. Produce release manifest

```bash
python paper/strong_mechanism/scripts/validate_study.py --release
```

The validator hashes configs, protocols, normalized data, scripts, figures, tables, and PDF without modifying source artifacts.
