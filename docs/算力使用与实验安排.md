# 算力使用与实验安排

## 1. 硬件与角色分工

当前可用算力分为三类：

1. 本机显卡：RTX 4070 Ti，约 12GB 显存。
2. 服务器显卡：RTX 3090 Ti，约 24GB 显存。
3. 强 judge：通过 API 调用 GPT-5.5。

整体策略：

> 本机负责探索和脚本验证，服务器负责正式训练和批量推理，GPT-5.5 API 负责强评估与小规模裁判校准。

不要试图让 4070 Ti 或 3090 Ti 完成所有顶刊级实验。它们适合完成大部分 LoRA 训练、谱分析、干预和中等规模评估；真正昂贵、强依赖模型能力的 judge 交给 API。

## 2. 本机 4070 Ti 的任务

4070 Ti 约 12GB 显存，适合做低成本快速迭代。

### 2.1 适合完成的任务

#### 2.1.1 代码开发与流程验证

本机优先用于：

- 训练脚本开发；
- SpectraSafe 正则项实现；
- LoRA adapter 保存与加载；
- 谱指标计算脚本；
- post-hoc scaling / pruning 脚本；
- 结果表合并脚本；
- bootstrap 和统计分析脚本；
- API judge 请求格式调试。

这些任务不应占用服务器时间。

#### 2.1.2 小模型 pilot

推荐模型：

- Qwen3-4B；
- Qwen2.5-3B；
- 其他 3B-4B 级别 instruct 模型。

推荐设置：

- 4-bit QLoRA；
- LoRA rank 8 或 16；
- batch size 1；
- gradient accumulation 1-4；
- max sequence length 512 或 1024；
- max samples 16-64；
- seed 1 个即可；
- family 先选 2 类：benign_task 和 explicit_malicious。

目标不是得到正式结果，而是验证：

- 训练流程是否稳定；
- 谱正则项是否能正常反传；
- adapter 权重是否能正确导出；
- layer-wise 谱指标是否能计算；
- unsafe/refusal 评估流程是否跑通。

#### 2.1.3 小规模机制检查

本机可以先做最小闭环：

1. 训练 vanilla LoRA。
2. 训练 SpectraSafe-global。
3. 计算每层 `||B||||A||` 和 `||BA||_2`。
4. 画 layer-wise 谱曲线。
5. 对 top-k 高谱层做 scaling。
6. 用少量 prompts 调 API judge。

如果这个闭环没有信号，不建议直接扩大到服务器大实验。

### 2.2 不建议本机承担的任务

4070 Ti 不建议承担：

- 7B 多 seed 全量训练；
- 14B 模型本地 judge；
- 多 backbone 完整实验；
- 大规模 HarmBench/AdvBench 生成；
- SaLoRA、Safe Delta、SPLoRA 的完整复现；
- 长上下文训练或推理。

本机的核心价值是快速试错，不是堆最终结果。

## 3. 服务器 3090 Ti 的任务

3090 Ti 约 24GB 显存，是正式实验主力。

### 3.1 适合完成的任务

#### 3.1.1 7B/8B 主实验

推荐主模型：

- Qwen3-8B；
- Qwen2.5-7B-Instruct；
- Mistral/Ministral 8B 作为跨模型验证。

推荐训练设置：

- 4-bit QLoRA；
- LoRA rank 8、16、32；
- batch size 1；
- gradient accumulation 1-8；
- max sequence length 1024；
- max samples 16-128；
- gradient checkpointing 开启；
- bf16 或 fp16 视环境稳定性决定。

服务器应负责正式训练以下 adapter：

- vanilla LoRA；
- SpectraSafe-global；
- mean-only；
- max-only；
- Frobenius regularization；
- orthogonal regularization；
- weight decay；
- 可选 SpectraSafe-layer-aware。

#### 3.1.2 机制发现实验

服务器负责生成正式机制数据：

- family-level adapter；
- dose-level adapter；
- seed-level adapter；
- layer-wise spectral profile；
- module-wise spectral profile；
- top-k spectral spike；
- `||B||||A||` 与 `||BA||_2` 对比；
- effective rank 和 singular value concentration。

#### 3.1.3 干预实验

服务器负责运行正式干预后的模型输出：

- 高谱层 scaling；
- 低谱层 scaling；
- 随机层 scaling；
- attention-only scaling；
- MLP-only scaling；
- 可选 top singular direction intervention。

服务器不一定需要本地 judge，只需要生成待评估回答并保存为 JSONL，后续交给 API judge。

### 3.2 可尝试但不作为主线的任务

3090 Ti 可以尝试：

- Qwen3-14B 4-bit 推理；
- 14B 小批量 LoRA；
- 14B 本地辅助 judge。

但这些不应成为主流程依赖。24GB 能跑不代表适合大规模稳定跑。强 judge 已经计划用 API，因此服务器应优先服务训练和生成。

## 4. GPT-5.5 API Judge 设计

### 4.1 定位

GPT-5.5 API 用作强 judge，而不是训练模型。

主要任务：

- 判断 harmful prompt 下模型是否 unsafe compliance；
- 判断 safety prompt 下模型是否保持 refusal；
- 判断 benign prompt 下是否过度拒答；
- 对输出进行结构化打分；
- 作为主结果或强评估结果。

### 4.2 模型名与接口处理

OpenAI 官方文档页面已出现 Latest: GPT-5.5 的入口，但实际 API 中的精确模型 ID 和账号权限仍应以 `/v1/models` 或平台控制台为准。

代码中不要硬编码模型名，建议使用：

```text
JUDGE_MODEL=gpt-5.5
```

或从配置文件读取：

```yaml
judge_model: gpt-5.5
```

如果账号暂时没有权限，应能切换为：

- 当前可用的最强 GPT-5.x 模型；
- 第二 judge 模型；
- 本地 14B judge 作为辅助。

### 4.3 Judge 输入格式

每条评估样本建议包含：

```json
{
  "sample_id": "...",
  "family": "...",
  "method": "...",
  "dose": "...",
  "seed": 1,
  "prompt_type": "harmful|benign|safety",
  "prompt": "...",
  "model_response": "...",
  "rubric": "..."
}
```

Judge 输出必须结构化：

```json
{
  "unsafe_compliance": 0,
  "refusal": 1,
  "safe_non_refusal": 1,
  "utility_score": 0.2,
  "reason": "..."
}
```

正式统计时只使用结构化字段，`reason` 仅用于人工检查和错误分析。

### 4.4 成本控制

API judge 不能一开始全量跑。

建议分三批：

#### 第一批：调试批

- 每个方法 10-20 条；
- 只验证 prompt、rubric、JSON 输出稳定性；
- 检查是否存在格式错误或 judge 过严/过松。

#### 第二批：pilot 批

- 每个方法 100-300 条；
- 用于判断主趋势；
- 决定是否扩大实验。

#### 第三批：正式批

- 只对最终方法、关键 baseline、关键 ablation 全量评估；
- 不要对所有失败支线全量评估；
- 对边界实验采用抽样评估。

### 4.5 多 judge 与人工校准

即使使用 GPT-5.5，也不建议完全依赖单一 judge。

建议加入：

- GPT-5.5 主 judge；
- 一个辅助 LLM judge；
- 100-200 条人工校准样本；
- 40-60 条双人复核样本。

论文中应报告：

- GPT-5.5 与人工标注的一致率；
- binary agreement；
- exact agreement；
- judge disagreement 的典型样例。

## 5. 实验阶段安排

## 阶段零：环境准备

时间：1-2 天

### 本机

安装或确认：

- Python；
- PyTorch CUDA；
- transformers；
- peft；
- bitsandbytes；
- datasets；
- accelerate；
- scipy；
- pandas；
- matplotlib；
- scikit-learn。

### 服务器

安装或确认：

- NVIDIA driver；
- CUDA；
- PyTorch；
- transformers；
- peft；
- bitsandbytes；
- flash-attn，如环境支持；
- accelerate；
- wandb 或 tensorboard；
- git-lfs。

### 产物

- `env_check.py`；
- `requirements.txt` 或 `environment.yml`；
- 本机和服务器环境记录；
- CUDA 与显存测试截图或日志。

## 阶段一：本机 pilot

时间：3-5 天

### 目标

用 4070 Ti 跑通最小闭环。

### 实验内容

模型：

- Qwen3-4B 或 Qwen2.5-3B。

方法：

- vanilla；
- SpectraSafe-global；
- mean-only；
- max-only。

数据：

- 2 个 family；
- 每个 family 16-32 条样本；
- 1 个 seed；
- 1 个 dose。

评估：

- 每个 adapter 20-50 条 prompt；
- GPT-5.5 API 小批量 judge。

### 成功标准

- 训练不爆显存；
- 谱指标能正常导出；
- SpectraSafe 能显著降低 global spectral norm；
- judge 流程能输出稳定 JSON；
- 至少看到一个方向性安全信号。

### 失败处理

如果 SpectraSafe 不能压缩谱指标：

- 先检查实现，不扩大实验。

如果谱指标压缩但安全无变化：

- 增加干预实验；
- 检查 prompt 和 judge rubric。

## 阶段二：服务器主实验第一轮

时间：5-7 天

### 目标

在 3090 Ti 上完成主模型的核心方法比较。

### 模型

推荐：

- Qwen3-8B 作为主模型；
- 保留 Qwen2.5-7B 作为历史可比模型。

### 方法

第一轮只跑：

- vanilla；
- SpectraSafe-global；
- mean-only；
- max-only；
- Frobenius；
- weight decay。

暂缓：

- orthogonal；
- SaLoRA；
- Safe Delta；
- SPLoRA；
- layer-aware。

### 数据

建议先跑：

- 4 个 family；
- 2 个 dose；
- 3 个 seed。

如果时间或显存压力大，先缩为：

- 4 个 family；
- 1 个 dose；
- 3 个 seed。

### 产物

- adapter 权重；
- 训练日志；
- 谱指标表；
- 生成回答 JSONL；
- API judge 结果 JSONL；
- 主结果表。

## 阶段三：机制分析与干预

时间：5-8 天

### 目标

把论文从方法实验提升为机制研究。

### 分析任务

在服务器或本机 CPU 上完成：

- layer-wise spectral curve；
- module-wise spectral curve；
- family-level spectral pattern；
- unsafe/refusal 与谱指标相关性；
- `||B||||A||` 与 `||BA||_2` 的代理有效性；
- effective rank 与 top singular value ratio。

### 干预任务

服务器生成输出，API judge 评估：

- top-k 高谱层 scaling；
- bottom-k 低谱层 scaling；
- random-k 层 scaling；
- attention-only scaling；
- MLP-only scaling。

推荐先用：

- 每个方法 1-2 个代表 adapter；
- 每个 adapter 100 条 prompt；
- alpha 取 0.25、0.5、0.75。

如果有明显信号，再扩大。

## 阶段四：方法升级

时间：4-6 天

### 触发条件

只有在阶段三发现明显层或模块敏感性时，才做 layer-aware SpectraSafe。

### 方法

设计：

```text
L = L_task
  + lambda_mean * sum_l w_l sigma_l
  + lambda_max * max_l w_l sigma_l
```

权重来源：

- high-risk layers；
- high-risk modules；
- correlation score；
- intervention score。

### 实验规模

不要一开始全量跑。

先跑：

- 1 个模型；
- 2 个 family；
- 1 个 dose；
- 2 个 seed。

如果优于 global，再扩大。

### 失败处理

如果 layer-aware 不提升：

- 不作为主方法；
- 放入负结果或局限；
- 保持 SpectraSafe-global 为主。

## 阶段五：强基线与跨模型验证

时间：7-12 天

### 强基线优先级

优先级一：

- Safe Delta；
- SaLoRA。

优先级二：

- Safe LoRA；
- SPLoRA。

如果时间不够，至少完整复现一个强基线，并清楚解释其他方法为何难以同构比较。

### 跨模型验证

推荐最小跨模型包：

- Qwen3-8B 主结果；
- Qwen2.5-7B 复现对照；
- Mistral/Ministral 8B 小规模验证。

副模型不必跑全矩阵，但至少应包含：

- vanilla；
- SpectraSafe-global；
- Frobenius 或 weight decay；
- 2 个 family；
- 2 个 seed。

## 阶段六：最终评估与写作

时间：7-10 天

### 最终 API judge 批次

只对以下内容全量 judge：

- vanilla；
- SpectraSafe-global；
- 最佳增强版；
- 最强普通正则 baseline；
- 一个安全强基线；
- 关键干预实验。

失败支线只做抽样 judge，不要浪费 API 成本。

### 统计

必须输出：

- mean；
- standard error；
- bootstrap 95% CI；
- family-level breakdown；
- seed-level variance；
- safety-utility tradeoff curve；
- judge-human agreement。

### 写作

中文初稿章节顺序：

1. 引言；
2. 问题设定；
3. 谱几何机制发现；
4. 干预验证；
5. SpectraSafe 方法；
6. 实验；
7. 讨论与局限。

## 6. 推荐实验优先级

### 6.1 必做

1. 本机 pilot 跑通。
2. Qwen3-8B 或 Qwen2.5-7B 主实验。
3. vanilla、SpectraSafe、mean-only、max-only。
4. Frobenius 和 weight decay 对照。
5. layer-wise 谱分析。
6. 高谱层、低谱层、随机层干预。
7. GPT-5.5 API judge。
8. bootstrap CI。

### 6.2 强烈建议

1. Qwen2.5-7B 与 Qwen3-8B 对照。
2. 一个 Mistral/Ministral 8B 跨模型验证。
3. Safe Delta 或 SaLoRA 强基线。
4. human validation 小样本。
5. safe non-refusal rate。

### 6.3 可选

1. top singular direction intervention。
2. SpectraSafe-layer-aware。
3. SPLoRA。
4. Adapter composition。
5. 本地 14B 辅助 judge。

## 7. 资源预算建议

### 7.1 本机预算

本机每天适合跑：

- 2-6 个小模型 adapter；
- 若干谱分析；
- 小规模 API judge；
- 图表和统计。

本机不应排长时间阻塞任务，以免影响写作和脚本开发。

### 7.2 服务器预算

服务器每天适合跑：

- 若干个 7B/8B QLoRA adapter；
- 批量生成回答；
- 干预后生成；
- 强基线训练。

建议采用队列式运行：

1. 先跑 vanilla 和 SpectraSafe；
2. 立刻生成和评估；
3. 确认有趋势后再跑其他 baseline；
4. 不要先把所有 baseline 全训练完。

### 7.3 API 预算

API judge 应按优先级使用：

1. 调试 judge rubric；
2. 主方法和 vanilla；
3. 关键消融；
4. 强基线；
5. 干预实验；
6. 边界实验。

每次 API 评估都必须缓存结果，避免重复计费。

## 8. 最小可行实验矩阵

如果目标是尽快形成可投初稿，建议最小矩阵如下：

### 主模型

- Qwen3-8B 或 Qwen2.5-7B。

### 方法

- vanilla；
- SpectraSafe-global；
- mean-only；
- max-only；
- Frobenius；
- weight decay；
- 一个强安全 baseline。

### 数据

- 4 个 family；
- 1-2 个 dose；
- 3 个 seed。

### 机制

- layer-wise spectral analysis；
- module-wise spectral analysis；
- high/low/random layer scaling。

### 评估

- GPT-5.5 API judge；
- 一个公开安全 benchmark；
- 一个效用 benchmark；
- bootstrap CI。

这个矩阵是 8 月投稿的现实底线。

## 9. 不建议当前做的事情

不建议一开始做：

- 14B/32B 本地全量训练；
- 多个强基线同时完整复现；
- 大规模 adapter composition；
- 全模型全 family 全 dose 全 seed 的盲目扩张；
- 在没有机制信号前做复杂 direction-aware 方法；
- 没有缓存的 API 大批量 judge。

当前最重要的是快速确认主线：

> 谱几何结构是否真的解释 LoRA 安全漂移，并且 SpectraSafe 是否比普通正则更有针对性。
