# 机制验证数据集使用标注

本项目采用 `mechanism_dataset_v1` 作为跨 backbone 机制验证的数据协议。它的目标不是训练一个通用安全模型，而是控制训练剂量并检验以下关系：

\[
\rho_t = \frac{\|\lambda_t g_{safe,t}\|}{\|g_{risk,t}\|+\|\lambda_t g_{safe,t}\|}
\quad\Longrightarrow\quad
\text{安全反弹与回答质量变化}
\]

## 数据用途标注

| split | 上游来源 | 用途 | 是否可调参 |
|---|---|---|---|
| `train_risk` | BeaverTails | 风险 LoRA 训练流 | 可以 |
| `train_safety` | PKU-SafeRLHF | 序列级安全监督/replay | 可以 |
| `train_utility` | Alpaca（仓库已有） | 正常能力保持 | 可以 |
| `train_control` | Alpaca shuffled response | 错配对照 | 可以，但不得当作自然 benign 基线 |
| `eval_beavertails` | BeaverTails-Evaluation | 分类别安全主评测 | 不可 |
| `eval_sorry_bench` | SORRY-Bench 2025 | 主 held-out / 改写泛化评测 | 不可 |
| `eval_harmbench` | HarmBench text test | 外部鲁棒性验证 | 不可 |

## backbone 使用规则

Qwen3、Llama 和 Mistral 必须使用相同的语义 prompt ID、样本数、有效 token budget、训练步数和 seed。不同 tokenizer、chat template 或 thinking mode 需要在实验 manifest 中显式记录；不能直接比较绝对 token logit 或未经标准化的谱值。

## 安全与合规

风险数据只用于受控研究、梯度审计和安全评估。日志、论文附录和模型输出不得直接暴露有害指令或可执行细节；保存输出时优先使用 sample ID、标签和哈希。BeaverTails、PKU-SafeRLHF 和 SORRY-Bench 等来源的许可/访问条款分别适用，仓库文件不重新授权这些数据。

## 可复现要求

每次实验必须保存：

1. `data/processed/mechanism_v1/manifest.json`；
2. 上游 revision 和 SHA-256；
3. 使用的过滤参数（类别上限、seed、最大长度）；
4. judge/classifier 名称和版本；
5. 训练/评测 split 的 sample ID 列表。

该标注不把数据集称为“人工重新标注集”；它是依据上游已有标签的确定性重采样和格式规范化。
